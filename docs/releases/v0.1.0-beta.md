# Release notes - Nimbus 0.1.0-beta

Release notes version: 1

Date: 2026-10-03

## High-level summary

Nimbus keeps a local folder in sync with any rclone remote on Linux. This beta
adds packages for Debian, Fedora, and Arch, so you can install Nimbus without a
compiler. The sync itself is unchanged since the alpha build.

## New features

- **Sync a whole remote, or one folder in it.** Type a bare name, as in
  `drive`, to sync the whole remote. Add a folder, as in `drive:/Documents`, to
  sync that folder only.

- **A tray icon with one icon for each phase.** The icon shows whether Nimbus
  waits, syncs, waits for you, or has no connection.

- **A window with the progress and the buttons that apply.** The window shows
  the phase, the progress, the time of the last run, and the last error. A
  button shows only when it applies.

- **A daemon that heals a lost connection on its own.** Before the next run, the
  daemon repairs the record that rclone left behind, so the retry stays
  incremental. Most lost connections need no action from you.

- **A resync that always asks first.** A resync lets the local copy overwrite
  each remote copy that differs. The window asks before it starts one, and it
  names the reason.

- **You choose what a conflict keeps.** By default the newer edit wins and the
  older edit is deleted. With `conflict_resolve = "none"`, both copies stay, as
  `name.conflict1` and `name.conflict2`.

- **More rclone flags for every run.** Set `extra_flags` for flags that one
  remote needs, for example `--drive-skip-shortcuts` for Google Drive.

- **A settings dialog that checks your keys before it saves.** When a key is
  wrong, the reason shows under the field that holds it. The daemon checks again,
  because the dialog is not the only client.

- **A settings dialog that works while the daemon is down.** It reads and writes
  the config file itself, so a save survives a daemon that does not run.

- **A desktop notification when the daemon refuses to start.** A config that
  does not load, or a bus name that another daemon holds, stops the unit. The
  notification says so, so you do not need the log.

- **A Start daemon button.** The window starts the systemd user unit when no
  daemon answers. The button replaces Sync now and Pause.

- **Packages for Debian, Fedora, and Arch.** Every release attaches one package
  for each of the three distributions.

## New features requiring configuration updates

- **`remote` and `local` name the two sides of the sync.** Set `remote` to the
  name of an rclone remote. Set `local` to a folder that exists, because the
  daemon refuses a folder that does not.

- **`conflict_resolve` and `conflict_loser` choose the outcome of a conflict.**
  They take no effect until a file changes on both sides, so you can set them
  at any time.

- **`extra_flags` adds rclone flags to every run.** Leave the list empty unless
  one remote needs a flag. See
  [rclone bisync](https://rclone.org/bisync/) for the flags that bisync takes.

- **An older build wrote a `path` key, and that key no longer exists.** The
  daemon stops with a message that names the unknown field. Delete the line, and
  put the folder in `remote` instead, as in `drive:/Documents`.

## Improvements

- **The tray icon takes the color of the desktop.** The icon has no color of its
  own, because no icon transport reads one. KDE and GTK each paint it with
  their own palette.

- **The window sets no header bar.** The caption comes from the desktop, so the
  window keeps the room for the state.

- **The error lines take the stock error color.** The theme of the desktop picks
  the color, so the line matches every other error on the desktop.

- **The icons fit the KDE grid.** Each icon now fills the tray size of 22 pixels
  and keeps the margin that the KDE guidelines ask for.

- **The settings dialog asks before it saves a move.** A moved `remote` or
  `local` has no record of a sync, so the dialog names the cost first.

- **The menu shows the phase in its first row.** The row is not a command, so it
  carries no button.

## API and D-Bus updates

- **One D-Bus interface on the session bus.** The name is
  `io.github.luckjmg.nimbus`, the path is `/io/github/luckjmg/nimbus`, and the
  interface is `io.github.luckjmg.nimbus1`.

- **Five methods, one property, and one signal.** The methods are `SyncNow`,
  `SetPaused`, `GetSettings`, `SetSettings`, and `Resync`. The property is
  `State`, and the signal is `Changed`.

- **The `State` signature is `(sdts)`.** The four values are the phase as a
  string, the progress as a double, the time of the last run as a Unix
  timestamp, and the last error as a string.

- **The `Settings` signature is `(ssttssas)`.** The seven values are `remote`,
  `local`, `interval_secs`, `debounce_secs`, `conflict_resolve`,
  `conflict_loser`, and `extra_flags`.

- **The phase is one of five strings.** The values are `idle`, `syncing`,
  `paused`, `error`, and `resync`. In the `resync` phase, the daemon waits until
  a client calls `Resync`.

- **A client in Rust must set `cache_properties(CacheProperties::No)`.** The
  daemon sends `Changed`, not `PropertiesChanged`. A cached proxy reports a
  stale state forever.

- **The sync mode was dropped.** Nimbus runs `rclone bisync` only. A proxy must
  not send a mode.

## Bug fixes

- **The tray icon no longer shows black on a dark panel.** The icon took no
  color from the desktop, so it fell back to black.

- **The window no longer leaves gaps at its corners.** The window size missed the
  edges that the CSS drew.

- **The buttons no longer take the focus when the window opens.** The first
  button took the focus, so a space bar sent a command.

- **The daemon no longer restarts in a loop when the config does not parse.** A
  refusal now exits with zero, so the unit stays stopped. Only a real failure
  restarts.

- **The settings dialog no longer wrote the defaults over a good config file.**
  When no daemon answered, the dialog showed the defaults and a save put them
  over the file. It now reads the file first.

- **The extra flags field no longer starts with a stray value.**

- **The error line in the window no longer accepts an edit.** The line took a
  click, and an edit looked like a setting.

- **A second tray instance no longer takes over the first one at random.** The
  application name reaches the running instance, so only one tray item exists.

## Known issues

- **The packages are for x86_64 only.** The build has one runner architecture, so
  there is no `aarch64` package yet.

- **A package does not enable the daemon unit.** An install runs with no session
  bus, so only you can enable it. Run this once after the install:

  ```console
  systemctl --user enable --now nimbusd.service
  ```

- **Debian ships an rclone that is older than the sync needs.** `bisync` left
  beta in rclone 1.71. The Debian package lists `rclone (>= 1.71)` as a
  recommendation, not a dependency, so the install succeeds. Install a newer
  rclone from the rclone apt repository or from a static build.

- **A tray click raises the window only while the window is hidden.** A window
  that is already open keeps its place, and a minimized window stays minimized.
  The compositor refuses a raise without a click of its own, and no standard
  tray protocol sends one. The taskbar entry flashes instead.

- **The daemon watches only the local folder.** A change that you make on
  another machine arrives on the next interval, which is 900 seconds by
  default.

- **A failed run waits for the whole interval before it retries.** There is no
  separate retry timer. Set `interval_secs` to a low value, for example `300`,
  when the connection is often down.

- **The panel can drop the tray item.** The tray logs the event and stays up,
  because the window still works. A panel reload brings the icon back.

- **The remote folder must exist before the first run.** Nimbus cannot create a
  folder on every remote. Some remotes, for example Google Drive, create the
  folder themselves.

## Notes for the next release

- The `sync` mode stays gone. It deleted remote files that no local copy had.
